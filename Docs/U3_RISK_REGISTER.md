## Safest testing ladder (use in this order)

1. **Editor Play Mode** (`GameStartup.unity` → Play): fastest loop; client role; Steam must be running. `[SOURCE: Provider.cs]`
2. **Local single-player development build** (`Window > Unturned > Build Tool > Build Test` → run from `Builds/Test`): catches editor-API leaks and build-only behavior. `[SOURCE: BuildTool.cs, .gitignore:62-63]`
3. **Dedicated local server + one local client**: editor flag `-DedicatedServerInEditor` or command line `+LANServer/{ID}` (+ `-OfflineOnly` to reduce backend traffic); verifies authority assumptions. `[SOURCE: Dedicator.cs:63,83-97,159; exact two-instance workflow RUNTIME]`

## Casual-change red flags (any of these ⇒ stop and get explicit user approval)

- Adding/removing/reordering fields in anything written by `save()`/`Block`/`River`.
- Renaming public types/members, changing signatures, or reordering enums.
- Touching `NetGen/`, `NetMessaging/`, `NetInvokable/`, or running Net Gen.
- Editing `steam_appid.txt`, `Status.json`, server visibility/browser code, HostBans, anti-cheat handlers.
- Moving/renaming assets, editing `.meta` files, or hand-editing `.unity`/`.prefab` YAML.
- Changing `Setup.Awake` / `Provider.awake` ordering or manager `DontDestroyOnLoad` structure.
